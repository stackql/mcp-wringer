# M4: Streamable HTTP

Added a Streamable HTTP adapter with spawned-target readiness checks, loopback-only attach by default, HTTP tracing, revision-specific headers and optional 2025 session handling. Normal exchanges use `node:http`/`node:https`; raw-socket cases use `node:net`/`node:tls`. Added an HTTP fixture, transport-specific fault generation and cited HTTP response oracles.

The shared `TransportSession` contract was added because the existing run loop assumed stdio. Core now selects an adapter through the transport registry, while generators, oracles, replay and inspection accept transport-neutral results.

The pinned specification at commit `0a11bf68c7ec4473526ec15589f592afcd12d1e8` does not define `MCP-Method` or `MCP-Name` headers for either supported revision. No such required headers were implemented; the HTTP fault generator covers revision-defined headers and an invalid HTTP method instead.

No runtime dependencies were added. The full check initially exposed an exit-observation race in stdio crash classification under load; the transport now waits briefly for a process exit after an `EPIPE` before classifying it. The final full check and matrix both passed.

Hosted CI run `37761766619` passed all six Ubuntu, macOS and Windows jobs on Node 22 and 24.
